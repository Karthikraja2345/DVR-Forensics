# Forensic Validation Plan & Ground Truth Benchmark
## SIH 2026 – Problem Statement 26150
### Multi-Vendor DVR/NVR Forensic Analysis Tool

---

## 1. Validation Philosophy

In digital forensics, software cannot rely on subjective claims or black-box predictions. Every output generated by this platform must be validated against **verifiable ground truth fixtures**.

> [!IMPORTANT]
> The platform must never fabricate validation statistics. All accuracy percentages, recovery scores, and performance metrics reported in the UI and reports are calculated directly from automated fixture test runs.

---

## 2. Ten Key Validation Benchmarks

| # | Validation Area | Metric & Target | Ground Truth Test Method | Pass Criteria |
|---|---|---|---|---|
| **1** | **Source Hashing** | $100\%$ Repeatability | Stream 100 iterations of identical fixture files through `DualHasher`. | Identical MD5 and SHA-256 digests across all runs ($0$ variance). |
| **2** | **Vendor Detection** | Multi-Signal Accuracy | Run `VendorDetector` against Dahua, CP Plus, Hikvision, and Generic fixtures. | Correct classification ($\ge 0.85$ conf) on known; `UNKNOWN` on ambiguous. |
| **3** | **Active Parsing** | $100\%$ Stream Recall | Parse `dahua_dhfs_sample_01.raw` containing 4 known active recordings. | All 4 recordings extracted with accurate channel, duration, and offsets. |
| **4** | **Deleted Recovery** | $100\%$ Carve Recall | Carve unallocated clusters containing 1 intentionally deleted H.264 clip. | Recovered clip matches ground truth SHA-256; confidence = `CONFIRMED`. |
| **5** | **Timestamp Normalization** | $0\text{ sec}$ Drift Error | Ingest raw hardware timestamp `1789123864` with documented UTC offset (+05:30). | Exact mathematical match with UTC reference time. |
| **6** | **Cross-Camera Narrative** | $100\%$ Ordering Accuracy | Aggregate events across `CAM-01`, `CAM-02`, `CAM-04`, `CAM-05`. | Chronological sequence strictly preserves true physical movement path. |
| **7** | **Media Integrity** | Container / NAL Validation | Evaluate carved video stream headers and NAL unit cadence. | Valid SPS/PPS header, valid IDR keyframe cadence, playable video stream. |
| **8** | **AI Analytical Isolation** | $0\%$ Evidence Mutation | Run motion analysis on working copy; hash original and working copy. | Hashes of video files remain completely identical before and after AI execution. |
| **9** | **Chain of Custody** | $100\%$ Tamper Detection | Ingest 10 sequential custody events; inject 1 bit modification into Event 4. | `verify_chain()` succeeds on unaltered chain; fails immediately on mutated chain. |
| **10** | **Throughput & Speed** | $\ge 250\text{ MB/min}$ | Measure carving and indexing throughput on raw disk image. | Completes parsing and carving within acceptable operational thresholds. |

## 3. Standard Forensic Fixture: `sample_case_001`

To ensure end-to-end reproducibility, the platform includes a controlled synthetic disk image: `forensic_fixtures/sample_images/dahua_dhfs_sample_01.raw`.

* **Storage Geometry**: $100\text{ MB}$ raw disk image ($204,800$ sectors of $512$ bytes).
* **Filesystem Signature**: Offset `0x00000000` = `DHFS` (Dahua Proprietary Filesystem 4.0).
* **Active Channels**:
  - `CAM-01`: Main Entrance Gate (Allocated, Start: `14:31:04`, Duration: `10s`, Offset: Sector $2,048$).
  - `CAM-02`: Internal Corridor (Allocated, Start: `14:31:11`, Duration: `10s`, Offset: Sector $4,096$).
  - `CAM-04`: Vehicle Parking Area (Allocated, Start: `14:31:18`, Duration: `10s`, Offset: Sector $6,144$).
  - `CAM-05`: Perimeter Exit Gate (Allocated, Start: `14:31:25`, Duration: `10s`, Offset: Sector $8,192$).
* **Deliberately Deleted Recording**:
  - `CAM-03`: Loading Bay / Secure Zone (Index marked deleted; H.264 NAL stream preserved in unallocated sectors $10,240$ to $12,288$).
* **Expected Carving Result**:
  - Carved Artifact ID: `ART-DEL-CAM03-20260911`
  - Status: `CONFIRMED`
  - Explanation: `Valid SPS (0x67), PPS (0x68), and IDR slices detected at sector offset 10240`.
